# Agentic Log Incident Analysis

This Track B task family evaluates read-only investigation of immutable,
multi-file incident evidence. It is intentionally broader than a single
synthetic pattern:

- `checkout-pool-regression` tests a deployment configuration regression,
  traffic as an exposing trigger and cross-service distractor rejection.
- `retry-queue-amplification` tests delayed operational effects, retry-driven
  queue amplification and a salient but non-causal error stream.
- `clock-skew-partial-recovery` tests chronology reconstruction when one host's
  timestamps are unreliable and only partial recovery is observed.

The first case and its v0.1 verifier are frozen inputs to already qualified
harness artifacts. It also has additive v2 task, card, hidden-truth and
reference files so the common three-case protocol can use one report contract;
the immutable log fixture itself is reused. The two later cases use the same
data-driven v0.2 report contract and verifier. No frozen v0.1 file was modified.
All cases are synthetic; their hidden references are used only after candidate
execution.

The common `mini-log-v0.2` and `pi-log-v0.2` paths are offline-qualified and
have completed excluded Qwen 3.8 machinery smokes on
`retry-queue-amplification`. Mini produced a valid report with 11/14 checks;
Pi's final response was rejected as malformed because it placed prose before
its JSON. Neither is measured capability evidence. The public report records a
control-layer protocol deviation and forbids model or harness ranking claims.
A durable three-case sweep controller was subsequently qualified and completed
the frozen v0.2 Capability Sweep. Its 0/30 strict result exposed a benchmark
alignment defect: visible tasks did not define `start_utc`, although the hidden
verifier required the first user-facing impact event. Historical v0.2 artifacts
and outcomes remain immutable and must not be pooled with a corrected version.

The additive v0.3 representation now covers all three cases. It preserves
report schema v2 but introduces new case identities, visible tasks, cards and a
15-check verifier. Every essential check has a candidate-visible marker;
incident start, last supplied observation and recovery status are separate.
Three references pass 45/45 checks, and targeted negative controls cover every
semantic dimension plus schema and representation boundaries.

Final-output handling is also predeclared. Exactly one intact JSON object may
be normalized out of a Markdown fence or surrounding prose, but internal JSON
is never repaired and ambiguous output is rejected. Semantic verified success
is primary. Strict transport compliance is reported separately. Mini and pinned
Pi 0.84.4 adapters are offline-qualified for this contract. The subsequent
small v0.3 confirmation showed that the temporal repair worked but found three
more evaluator false-negative classes: hidden exact scope strings, an exhaustive
evidence-set requirement where sufficient counter-evidence was requested, and
hidden reference-author evidence roles. Its official outcomes remain immutable
and excluded from model-ranking evidence.

Additive v0.4 repairs those findings. Descriptive scope labels receive a narrow
lexical normalization without domain-synonym guessing. Rejected hypotheses use
predeclared alternative sufficient evidence groups. The clock-skew truth follows
the visible direct-role guidance without requiring duplicate event roles. The
report schema, temporal definitions, response-envelope policy and runtime
boundaries remain unchanged. Both Mini and pinned Pi 0.84.4 have separately
versioned, offline-qualified v0.4 adapters. Its six-cell confirmation completed
technically but human calibration exposed three more measurement defects:
negation-blind free-text substring matching, rejection of compatible component
detail in descriptive scope and ambiguity about which rejected-hypothesis field
attaches evidence.

Additive v0.5 repairs those defects without changing v0.4 or its official 1/6
result. Scope is now a machine-scored selection from exact case-specific IDs;
component detail belongs in prose or citations. Only IDs in
`rejected_hypotheses[].evidence_ids` count as attached counter-evidence, and the
visible task says so. All other machine-scored categorical claims use complete
candidate-visible codebooks. The verifier no longer infers assertion polarity
from free-text substrings: deterministic structured success and the mandatory
supplemental human or fixed-LLM free-text grounding review are separate outcome
layers. Three references pass 45/45 checks, both versioned harness adapters pass
offline boundary tests, and no model was contacted. A new small excluded
confirmation has now been frozen after the implementation commit, with Qwen
3.8, both harnesses and all three cases represented exactly once. Its controller
is qualified offline, but no repository live-authorization artifact exists.
Any execution requires a later clean-window authorization plus the real
resource and Pi Seatbelt gates. A broad v0.5 model sweep remains withheld.
